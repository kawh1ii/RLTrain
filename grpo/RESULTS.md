# 单卡实测结果与结论边界

硬件为 RTX 4090 24GB，驱动 595.71.05；PyTorch 2.13.0+cu130、Triton 3.7.1。源码冻结后完成 42 项测试、29 个阶段、74 组算子方法测量和 14 次模型计时运行。完整样本、日志、环境与散列位于 `results/final/`；可用 `python docs/verify_experiments.py` 无 GPU 复核。

## 可以写进简历的收益

H=896、V=151936、BF16、可训练输出头；N 为损失位置数。算子计时包含 forward 和 backward。每次 2 次预热、7 次测量，三个种子分别取全部样本中位数，再取跨运行中位数。峰值为各运行 maximum allocated bytes 的中位数；不是 nvidia-smi 显存。

| N | eager ms / GiB | torch.compile ms / GiB | 本实现 ms / GiB |
|---:|---:|---:|---:|
| 512 | 6.912 / 1.140 | 4.537 / 0.705 | 4.254 / 0.589 |
| 2048 | 28.396 / 3.754 | 18.750 / 2.014 | 15.871 / 0.784 |
| 4096 | 55.811 / 7.232 | 37.639 / 3.755 | 32.496 / 1.044 |

N=4096 相比编译对照，耗时降低 13.7%，allocated 峰值降低 72.2%。收益来自不保留完整 N×V logits、词表遍历直接写出 gradW、累加较小 FP32 gradH，以及自写 Triton 归约/损失导数/原地梯度内核。GEMM 使用 cuBLAS，分块线性损失是已有技术。

## 真实模型：省显存，不能声称稳定提速

Qwen2.5-0.5B-Instruct，FP32 master / BF16 AMP，fused AdamW；固定同一批 16 条 GSM8K 真实生成轨迹、3830 有效响应 token、microbatch 8。每次运行 4 个优化器步，第 1 步为预热；三个运行各取余下 3 步中位数，再取跨运行中位数。计时包含 backbone、损失、反向和 optimizer，不包含生成、奖励与数据准备。

| 实现 | 训练步 ms | allocated 峰值 GiB |
|---|---:|---:|
| eager | 263.077 | 16.463 |
| torch.compile | 255.788 | 14.724 |
| 本实现 | 259.091 | 13.758 |
| 固定版本 Liger | 1012.446 | 14.016 |

本实现相对 compile 省约 6.6% 显存、耗时增加约 1.3%；相对 eager 省约 16.4% 显存、耗时下降约 1.5%。microbatch 4 的单次对照中，本实现 490.914 ms 对 eager 478.510 ms，存在回退。H=2048 的算子扩展也慢于 compile（8.759 vs 7.912 ms）。不能把主形状收益外推到所有模型/批大小。

Liger 固定提交 `8c7a5078318da1295dc3ca445f9d85e9e9e153f5`，显式 GRPO，核对 285 个源文件及导入路径。本轮 chunk_size=1 是按序列分块的实现配置；结果只代表此版本、配置和机器，不能声称全面优于 Liger。冻结输出头扩展中 Liger 显存更低（0.304 vs 本实现 0.530 GiB）。同公式的 Torch 手写反向和 checkpoint 对照均保留在完整报告中。

## 数值验证与未通过项

42 项单元测试包括 FP64 有限差分、三步 Adam 更新、裁剪分支、微批全局归一化、EOS、冻结头、非整除词表以及 GPU FP32/BF16。真实模型全部初始参数一致，全部首步梯度检查在预设容差内。

| 相对 eager | 首步梯度相对 L2 / cosine | 三步实际更新相对 L2 / cosine |
|---|---|---|
| compile | 0.01343 / 0.999910 | 0.17609 / 0.984518 |
| 本实现 | 0.01403 / 0.999902 | 0.13573 / 0.990837 |
| Liger | 0.01409 / 0.999901 | 0.18212 / 0.983353 |

三种 BF16 实现的实际更新向量都未通过最初 relL2<0.1 且 cosine>0.995 的阈值。保留原阈值和失败结果；在 eager/compile 也失败后，该项调整为明确诊断，不计入通过门槛。所谓“完成29阶段”不代表所有数值诊断通过。不能声称 BF16 训练轨迹等价或生产无损替换。早期用最终权重相对误差作判断容易被预训练权重范数掩盖，现已改为实际更新向量，排错历史保存在 `docs/DEBUG_LOG.md` 和 `results/development/`。

## 数据边界

固定 GSM8K 前四道符合长度约束的训练题，每题生成四条响应。128-token 尝试全部截断且优势为零，原样保留。256-token 批有16个非零优势，但正确答案数为0/16，非零训练信号来自预定义长度惩罚。这里只验证训练计算路径和资源，不证明数学能力、收敛或完整 RL 流水线吞吐改善。

原多卡架构对比归档在 legacy；旧2.13倍不作为新版收益。远端实验已结束，实例保持开机，GPU空闲。
