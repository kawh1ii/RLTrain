# 面试解释路线

## 用一分钟讲清贡献

“原来做过多卡 RL 训练系统编排，但对比受资源放置和通信路径影响。我进一步把一个明确模块拆出来：大词表 GRPO 线性头损失。先写独立参考和梯度推导，再实现 Triton LSE/损失导数/原地梯度内核，自定义反向分块重算。最初按 token 分块的版本慢且缓冲大，后来改为按词表遍历、一次写出 dW，缩小外部累加状态。最后对照 eager、compile、checkpoint 和 Liger，分别量化算子与真实模型训练步。”

具体显存、耗时、精度数字只使用最终 RESULTS.md 和原始表。不要拿开发轮的最优点或旧 8 卡 2.13× 当新版结果。

## 从代码回答四个问题

1. **省在哪里？** 打开 `fused.py`，说明没有跨前后保存 `N×V` 的概率/梯度矩阵。词表块内的 logits 在反向被原地覆盖；dW 分块一次写出，FP32 累加的是较小的 dH。输入权重和最终 dW 仍然存在，不能把 256MiB 工作块说成整步总显存。
2. **数学为什么对？** 推导 `g=dL/dlogp`，解释正优势上界、负优势下界的零梯度分支，以及 KL 的 `1-exp(ref-logp)`。再由 log-softmax 导出 `dZ=g(onehot-p)` 和两个 GEMM。用 FP64 gradcheck 和优化器更新检验，不能只比较 loss。
3. **微批为什么容易错？** 两个响应长度不同，序列均值和 token 均值不是同一目标；微批重新归一化再累加会把权重放大。先计算完整优化器批的权重，再切片；Liger 需乘 micro_B/full_B。
4. **怎样保证真在优化训练？** 除了头部微基准，还运行 Qwen 全模型前向、反向和 AdamW，用相同冻结 token、奖励、掩码、旧/参考概率与初始化。计时中不做梯度 CPU 快照，避免验证开销污染性能。

## 为什么不重写 GEMM

本轮瓶颈来自中间状态、遍历方式和归约融合，GEMM 继续使用 cuBLAS。只宣称自己写了列出的 Triton 归约、损失梯度和自定义反向，不说自己实现了高性能矩阵乘、训练框架或 CUDA 通信库。

## 为什么比较 torch.compile 和 Liger

朴素 eager 大矩阵容易打败，但不足以证明优化有意义。compile 是直接可用的强对照；Liger 已有分块 GRPO 实现，所以不能把分块思想说成新算法。对照必须统一目标函数、beta、epsilon、序列均值、掩码、dtype、训练梯度需求和 forward+backward 时钟。

若比 compile 省显存但更慢，就说清楚这是内存/耗时取舍；若只有某个大词表形状有收益，不能外推全模型或所有训练场景。

## 为什么 BF16 更新会不一致

小的数值差异可能改变优化器后续更新，数学梯度正确不代表所有混合精度训练轨迹一致。项目保留 eager/compile 对照的漂移，比较真实更新向量而非被初始权重掩盖的最终向量。FP64 检查和 GPU 数值容差分别说明实现与精度边界；不说“完全等价”“无损替换”。

## 为什么数学正确率为零也保留这批

系统验证重放真实生成内容和明确的标量奖励；该批的非零优势来自预先定义的长度项。它证明非零损失梯度与优化器路径，不证明 GRPO 学会解题。没有删除错答或临时改奖励来制造学习效果。要研究收敛，需要更多独立数据和长训练，这不是本轮的结果。

## 与原多卡项目的关系

4090 无 NVLink 只是限制了硬件互联条件，不否定所有多卡实验。原 8 卡经历可讲 NCCL、并行分组、资源隔离与 SHM 诊断；新版主贡献是单卡上可审查的计算和内存实现。没有用单卡数据声称验证了分布式扩展性，也不借旧架构倍数给新算子背书。
